# 0. はじめに

## この教材のゴール

**Icebergは未経験だが、データ基盤の経験は多少ある人**が、Icebergのテーブルフォーマットを使って、従来のデータ基盤と同じようにデータを扱えるようになること。

Icebergのスペシャリストになることは目指しません。目標は、**Icebergを使うプロジェクトに、要件定義や設計といった上流工程から参画できる**レベルです。そのために、内部構造は「設計判断に必要な範囲」までに絞り、各章の最後に「設計時に決めること」を置いています。

## 想定する読者

- S3 / ADLS2 / GCS などのオブジェクトストレージ、Parquet、パーティションといった言葉は知っている
- DWHやデータレイクの構築・運用に関わったことがある
- Icebergという名前は聞いたことがあるが、「なぜ必要なのか」「何が従来と違うのか」は説明できない

## 各章の書き方

新しい概念は、次の順番で説明します。

1. **なぜ必要か**（目的と意図）
2. **無かったらどう困るか**
3. **ユースケース**
4. **他に取り得る手段**
5. **既に知っているものでいうと何に近いか**

その後、実際に手を動かして確かめる節が続きます。

## 正直さについての約束

- 「手を動かして確かめた」と書いた内容は、実際に動かして確認したものだけです。
- 確認していない内容は、その旨を明記します。
- 書籍などの他の資料の文章や資材は、そのまま流用せず、自分の言葉で書き直しています。
