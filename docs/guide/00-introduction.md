# はじめに

## この教材のゴール

**Icebergは未経験だが、データ基盤の経験は多少ある人**が、Icebergを使って、従来のデータ基盤と同じようにデータを扱えるようになること。

Icebergのスペシャリストになることは目指しません。目標は、**Icebergを使うプロジェクトに、要件定義や設計といった上流工程から参画できる**レベルです。

## この教材の進め方

用語の解説を順番に並べるのではなく、**架空の小売チェーン「ミドリマート」のデータ基盤担当（あなた）が、現場で困りごとにぶつかっていく物語**として進めます。

- 話の中で疑問が生まれたら、その場で「ここでこう思いませんか？」と答えます
- あとから引けるように、疑問は [よくある疑問](/guide/faq) にもまとめます
- 実際に手を動かして確かめた内容だけを書きます（確認していないことは明記します）

## 読者に想定している前提

- S3 / ADLS2 / GCS のようなオブジェクトストレージ、Parquet、パーティションという言葉は分かる
- DWH（Snowflake、BigQuery など）やデータレイクの構築・運用に関わったことがある

## 準備するもの

- DuckDB（CLI）
- ターミナル

クラウドのアカウントも、課金も要りません。

## 物語の予定

| 話 | あなたが直面すること | この話で分かること |
|---|---|---|
| [第1話](/guide/01-monday-morning) | 先月の1件を直して、と言われる | Parquetのデータレイクで、1行を直すだけでも何が大変か |
| 第2話（予定） | 「DWHを使えばよかったのでは？」 | 従来のDB/DWHと、何が違うのか |
| 第3話（予定） | 「Icebergって、そもそも何？」 | Icebergの正体（仕様であること）と、中身の層構造 |
| 第4話（予定） | Hive/Parquetのままとの違いを確かめる | 同じ訂正が、Icebergだとどう変わるか |
| 第5話（予定） | 実際にテーブルを作って、更新して、戻す | 作成・更新・履歴を、ファイルを開いて確認する |
| 第6話（予定） | 使い始めて困ること | 小ファイル、メンテナンス、カタログの運用 |
| 第7話（予定） | 「うちは、使うべき？」 | メリット・デメリット、ユースケース、使わない選択 |

## 正直さについての約束

- 「手を動かして確かめた」と書いた内容は、実際に動かして確認したものだけです。
- 書籍などの他の資料の文章や資材は、そのまま流用せず、自分の言葉で書き直しています。
